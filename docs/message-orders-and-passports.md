# Из сообщения в заказ и QR-паспорт

## Из обращения в заказ

На экранах «Обзор» и «Заказы» появилась кнопка «Из сообщения в заказ». Владелец вставляет обращение, просматривает предложенные поля, исправляет их и нажимает «Подтвердить и создать». До подтверждения клиенты и заказы не создаются.

Пример свободного текста:

```text
Нужна уборка квартиры завтра в 15:00, бюджет 25 000 ₸.
Меня зовут Айдана, +7 700 111 22 33.
```

Пример с явными полями:

```text
Қызмет: Пәтер тазалау
Аты: Айдана
Телефон: +7 700 111 22 33
Бағасы: 25 000 теңге
Мерзім: 15.11.2026
```

Разбор локальный, по правилам RU/KK; внешняя языковая модель и передача обращений стороннему провайдеру не используются. Это ограниченный помощник ввода: он распознаёт явные подписи/фразы, телефон Казахстана, цену в KZT, ISO/дд.мм.гггг и сегодня/завтра/бүгін/ертең. Сложные договорённости, несколько услуг и неявные даты нужно уточнять вручную. Несколько разных сумм/дат не выбираются автоматически, иностранная валюта не конвертируется. Денежные значения передаются десятичными строками; относительные даты считаются по серверному времени Алматы.

При точном совпадении нормализованного телефона предлагаются до пяти клиентов только своей компании. Существующий клиент выбирается человеком; автоматического объединения контактов нет. Одна услуга с количеством 1 переносится в заказ. Полный исходный текст предлагается как редактируемый внутренний комментарий; время из сообщения остаётся в комментарии, поле срока хранит дату.

Подтверждение создаёт нового клиента (либо использует выбранного), заказ, услуги, номер, аудит и квитанцию идемпотентности в одной Serializable-транзакции. При потере ответа повтор с тем же ключом и данными возвращает тот же заказ; изменение данных под использованным ключом отклоняется. После неопределённой ошибки форма сохраняет отправленные данные для повторной отправки. Исходный текст не копируется в аудит.

API: `POST /api/message-orders/preview` и `POST /api/message-orders`. Только OWNER своей компании, строгие контракты, Origin, лимиты. Preview не пишет бизнес-данные.

## QR-паспорт заказа

В карточке заказа есть кнопка «QR-паспорт заказа». Владелец добавляет снимки «до/после», явно отмечает «Показать это фото клиенту по ссылке» и выпускает QR-паспорт. Публикация фото по умолчанию выключена. Назначенный сотрудник открывает фото из активной задачи, привязанной к заказу; он может загрузить фото и удалить свои снимки, но не выпускать/отзывать ссылку. После переназначения или завершения активных задач доступ сотрудника прекращается.

При выпуске ссылки интерфейс показывает QR, адрес, срок действия и скачивание PNG. Повторный выпуск отключает предыдущую ссылку. Если исходный ответ потерян, следует выпустить новую ссылку: исходный токен не восстанавливается из БД.

Публичная страница `/passport#token=…` не требует входа. Она показывает имя компании, номер, название, текущий статус, дату и только опубликованные фото. Телефоны, имя клиента, внутренние комментарии, цены, платежи, задачи и документы в ответ не входят. Название заказа и сами фото могут содержать чувствительную информацию: перед публикацией их проверяет команда. Любой обладатель ссылки может читать страницу и оставить отметку выполнения.

Ссылка содержит случайный токен 256 бит во фрагменте URL, который не передаётся при HTTP-навигации. В API токен отправляется в JSON POST, в БД хранится SHA-256. Нет токена в query/path и аудите. Срок ссылки — 30 дней; проверяется на каждом чтении и подтверждении, есть отзыв. API не кэшируется; страница исключена из индексации и задаёт `no-referrer`. Уже скачанные данные невозможно отозвать, поэтому отзыв запрещает последующие запросы, а не удаляет сохранённые получателем копии.

Клиент видит этапы работы и может подтвердить результат только при статусе COMPLETED, отметив ознакомление. Подтверждение проверяет актуальные версии заказа и ссылки в Serializable-транзакции; повтор не дублирует аудит. Изменение заказа, добавление/удаление фото или перевыпуск ссылки делает старую отметку неактуальной. Это отметка обладателя ссылки, без проверки личности, ЭЦП, договора или подтверждения оплаты.

### Фотографии

До 6 снимков на заказ; в API принимаются до 300 КБ входных JPEG/PNG/WebP в base64. Браузер принимает файл до 10 МБ и сжимает его перед отправкой. Сервер проверяет сигнатуру и формат, ограничивает декодирование 12 млн пикселей, запрещает анимацию и SVG, повторно кодирует JPEG до 1200 × 1200 без увеличения и метаданных. Итог не более 200 КБ; снимки хранятся приватно в PostgreSQL BYTEA, а не в публичном каталоге. Резервная копия БД должна включать и эти данные. Истечение ссылки не удаляет фото из CRM; удаление доступно в карточке.

API управления: `GET /api/orders/:id/passport`, `POST/DELETE /api/orders/:id/passport/link`, `POST /api/orders/:id/passport/photos`, `DELETE /api/orders/:id/passport/photos/:photoId`. Анонимные endpoints: `POST /api/passport/read` и `POST /api/passport/confirm`. Публикация/отзыв — только OWNER; чтение и работа с фото сотрудников требуют текущего активного назначения.

### Локальная демонстрация

При `WEB_ORIGIN=https://localhost:8443` QR ведёт на этот же компьютер. Чтобы открыть его камерой телефона клиента, нужен доступный телефону HTTPS-домен и корректный `WEB_ORIGIN`. Сетевой доступ, домен и внешний сервер эта итерация не публикует.

## Проверки

```powershell
npm run check:structure
npm run typecheck
npm test
npm run build
# С запущенным API и БД; тестовая почта local
$env:WEB_ORIGIN='https://localhost:8443'
$env:MAIL_DELIVERY='local'
$env:PASSWORD_RESET_DELIVERY='local'
node --test tests/smart-orders.integration.mjs
# Edge, запущенный HTTPS
$env:NODE_EXTRA_CA_CERTS=(Resolve-Path '.local/caddy/pki/authorities/local/root.crt').Path
$env:TEST_WEB_URL='https://localhost:8443'
$env:PLAYWRIGHT_CHANNEL='msedge'
npx playwright test tests/browser/smart-orders.spec.ts
```

Тесты создают собственные организации и удаляют только их. Проверены парсер RU/KK и время Алматы, неоднозначности, атомарность, потеря ответа, параллельные повторы, границы компаний, роли/переназначение, строгие контракты, фото/приватность/метаданные/лимит, независимое декодирование QR через jsQR, смена/отзыв/истечение ссылок, версии и параллельные подтверждения, мобильный интерфейс и RU/KK/EN. Успешный прогон не является гарантией отсутствия ошибок или готовности к внешнему запуску.
