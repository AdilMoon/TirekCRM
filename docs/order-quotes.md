# Смета и допработы

1. Откройте заказ и выберите «Смета и допработы». Основная смета использует текущие позиции, количества и цены заказа. Создайте ссылку и отправьте её клиенту.
2. Клиент увидит состав работ, стоимость и номер версии без входа в CRM. Он отмечает согласие с перечнем и суммой и нажимает «Согласовать предложение». Для нового заказа согласование основной сметы переводит статус в «Согласован».
3. После основной сметы укажите допработы отдельными позициями. Клиент увидит предложения, цену до допработ и новый итог. При согласовании позиции и сумма добавляются к заказу. Повторное подтверждение возвращает записанное время согласования.
4. Владелец может обновить экран и посмотреть список последних 30 версий. Выданная ссылка показана один раз. Если её нужно перевыпустить, отзовите текущую и создайте новую. Отзыв принятой ссылки закрывает доступ к странице, а запись согласования остаётся в заказе.

В заказе действует одно ожидающее предложение. Ссылка работает семь дней. Изменение клиента, названия, позиций или суммы делает несогласованную версию устаревшей. Оплата, назначение и внутренние заметки сами по себе не меняют коммерческие условия. После принятия основной сметы её позиции защищены от обычного редактирования. Допработы расширяют их после отдельного согласования. Для завершённого или отменённого заказа принятие новой версии прекращается.

## Telegram и CRM

На момент согласования система находит исполнителей активных задач этого заказа. Каждый получает одно уведомление в CRM, а для подключённого Telegram создаётся запись доставки в той же транзакции. В сообщении о допработах указаны номер заказа, согласованные наименования и количества. Поля цен, контактов клиента, внутренних заметок и ссылки согласования исключены. Перед отправкой проверьте клиентский текст позиций, который увидят также исполнители.

Бот повторно проверяет привязку и текущее назначение перед доставкой. Уведомление для закрытой или переназначенной задачи пропускается. Доставка повторяется при временном отказе Telegram, а назначение задачи после уже состоявшегося согласования использует обычное уведомление о назначении.

## Доступ по ссылке

В базе хранится хеш случайного токена. Токен передаётся во фрагменте адреса, API получает его в теле POST. Доступ истекает через неделю и отзывается из истории. Ссылка подтверждает действие её обладателя; проверка личности и юридическое подписание требуют отдельного процесса. В локальном режиме ссылка открывается на том же компьютере. Для отправки внешнему клиенту нужен доступный ему HTTPS-адрес и настроенный `WEB_ORIGIN`.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/orders/:id/quotes` | Владелец видит версии своего заказа. |
| `POST /api/orders/:id/quotes` | Владелец выпускает BASE или EXTRA с текущим `orderVersion`. |
| `DELETE /api/orders/:id/quotes/:quoteId/link` | Владелец отзывает ссылку своего заказа. |
| `POST /api/quote/read` | Клиент получает снимок по `token`. |
| `POST /api/quote/accept` | Клиент передаёт `token`, `revision` и `agreed: true`. |
