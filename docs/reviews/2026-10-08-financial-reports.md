# Адверсариальное ревью — финансы и документы, 2026-10-08
Проведено после реализации как отдельный проход самим исполнителем. Это не независимый внешний аудит и не заявление о готовности коммерческого релиза.

## Область
ReportsModule, общие схемы поиска, фильтры/пагинация, поиск заказов в финансовых формах, отображение денежных сумм, права на новые маршруты, миграция индексов.

## Найдено и исправлено
1. **Потеря тиынов в UI больших итогов (P1).** Исходный formatMoney преобразовывал строку в Number. Регрессионный тест воспроизвёл 180143985094819.82 → отображение ...819,80. Исправлено: BigInt для целой части и точная дробная часть с Intl.formatToParts. Проверены также предельная сумма NUMERIC(18,2), -0.01 и -0.00 на трёх языках.
2. **Недопустимый символ в поиске (P2).** Запрос q=%00 доходил до PostgreSQL и возвращал 500. Тест сначала упал с фактическим 500 вместо 400. Общая query-схема теперь отклоняет нулевой символ до обращения к БД; повторная проверка прошла.
3. **Нулевой год в периоде (P2).** Общая ISO-схема принимала 0000-01-01, PostgreSQL возвращал ошибку, API — 500. Воспроизведено интеграционным тестом. Для отчётов ограничены поддерживаемые годы 0001–9999, некорректная дата возвращает 400.
4. **Неоднозначность архивных дат (P2).** Общий краткий формат не содержал год. В новых списках операций и документов год отображается явно.

## Опровергнутые гипотезы
- Сотрудник читает отчёт напрямую: GET новых маршрутов возвращает 403, без сессии — 401.
- Можно подставить чужую организацию: лишнее поле отвергается; foreign orderId даёт пустую выборку. Отдельная компания получает только собственные операции/итоги.
- Страница и итог расходятся из-за разных фильтров: общий SQL-фрагмент фильтра и RepeatableRead; 411 операций проверены на пяти страницах и на пустой странице за пределами результата.
- UNION потеряет записи при совпадении id: UNION ALL, сортировка с kind и составной ключ UI; совпадение UUID в Payment/Expense покрыто тестом.
- SQL-подобный текст и wildcard расширят выдачу: параметризованный буквальный поиск, тесты кавычек, % и _.
- Конец дня теряет доли секунды или не учитывает смену пояса: проверены миллисекунда перед/на границах 2026 и историческая граница 2020.
- Переименование клиента/заказа меняет поиск акта: поиск идёт по неизменному снимку, подтверждено после правок живых записей.

## Проверки на момент ревью
- Полный набор API: 24 TAP-проверки пройдено; после последнего исправления нулевого года профильный набор отчётов повторно прошёл (7 TAP-проверок).
- Денежная арифметика и локализация: 6 тестов пройдено.
- Типы, структура и сборка: прошли.
- Браузерная проверка: пять существующих сценариев прошли; новый шестой сценарий прошёл при отдельном повторном запуске после уточнения двух неоднозначных тестовых селекторов. Проверены 205 архивных операций/актов, заказ за пределами первых 200, оплата, создание акта, точная сумма, RU/KK/EN и ширина 390px.
- Визуально просмотрены снимки финансов на компьютере и документов на телефоне; переполнения страницы не обнаружено.

## Оставшиеся ограничения
Нет замера нагрузки на больших объёмах; substring/JSON-поиск и большие offset требуют оценки на пилоте. Offset между запросами может сдвигаться. Период — дата записи, а не отдельная дата фактической операции. Старые совместимые маршруты по-прежнему возвращают 200 записей, но UI их не использует. Формат API проверяется функциональными тестами, fuzzing и независимый security review не выполнялись.
