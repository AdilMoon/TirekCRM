# Карточка клиента: история и оплаты

Путь: **Клиенты → История и оплаты** в строке нужного клиента. Имя клиента по-прежнему открывает редактирование; отдельного пункта меню нет. В карточке доступны контакты, общие показатели, поиск заказов по названию/номеру, фильтр статуса и «Только с остатком к оплате». Переход к заказу открывает обычную карточку, где можно записать полученную оплату, создать счёт и продолжить работу. Кнопка редактирования клиента использует свежую версию записи из API.

## Значение показателей

- **Заказы клиента** — все текущие связанные заказы, включая отменённые и бесплатные повторные выезды. Отдельно показаны активные (`NEW`, `CONFIRMED`, `IN_PROGRESS`) и выполненные.
- **Стоимость заказов** — текущая стоимость всех заказов, кроме отменённых. Сметы и счета повторно не суммируются.
- **Оплачено** — сумма платежей за вычетом возвратов по этим заказам. Это не выручка за выбранный период и не прибыль.
- **Остаток к оплате** — сумма положительных остатков отдельных неотменённых заказов. Переплата одного заказа не закрывает остаток другого автоматически. Бесплатные повторные выезды имеют нулевой остаток.

Поиск и фильтры меняют **только список**, а общая сводка остаётся по всему клиенту. Это явно указано на экране. По умолчанию 20 строк, новые сверху, при равных датах порядок определяется ID. Отменённый заказ остаётся в истории со статусом, но его остаток равен нулю. Дата в списке — дата создания заказа, локализованная в Алматы.

Данные относятся к текущим связям заказов с клиентом и текущим суммам. Это оперативная сводка, а не банковская сверка, юридическое подтверждение долга или исторический бухгалтерский регистр. После изменений из другого сеанса нажмите «Обновить» либо откройте карточку заново.

## API

`GET /api/clients/:id/overview?q=&page=1&pageSize=20&status=COMPLETED&unpaid=true`

`status` и `unpaid` необязательны; передаётся только `unpaid=true`, без фильтра параметр отсутствует. Схема строгая, организация берётся исключительно из сессии. Для неизвестного клиента и клиента чужой организации — 404; без сессии — 401; сотруднику — 403. Ответ `no-store`, маршрут ограничен 60 запросами/минуту на IP вместе с общими ограничениями приложения.

Ответ: `client`, `summary`, `items`, `total`, `page`, `pageSize`, `pages`. `summary` не зависит от фильтров; `total` — число строк с фильтрами. Контакты и финансовая сводка читаются в одной RepeatableRead-транзакции. Платежи/возвраты агрегируются группами, без дополнительных запросов на каждый заказ. Денежные итоги рассчитываются в PostgreSQL `numeric`, возвращаются десятичными строками и форматируются без JS Number.

Проверки: `tests/client-overview.integration.mjs` и `tests/browser/client-overview.spec.ts` (Microsoft Edge). Они используют отдельную QA-базу и созданные тестами организации.
