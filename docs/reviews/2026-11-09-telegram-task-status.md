# Telegram: статусы задач и недоступное фото

## Изменение

Карточка TODO содержит «Начать работу», IN_PROGRESS — «Завершить задачу». Результат сразу сохраняется через существующий TasksService вместе с аудитом TASK_STATUS_CHANGED/source=TELEGRAM и уведомлением владельцу. Карточка показывает актуальный статус. Сообщения доступны на RU/KK/EN.

При проверке пользовательской ошибки прежняя задача из нашей изолированной тестовой организации оказалась DONE, версия 5. Активная задача нужна для загрузки фото; ограничение сохранено. Старая кнопка фото теперь объясняет, что задача закрыта. Перед завершением карточка напоминает отправить фото. Новая активная задача для проверки создаётся только в том же тестовом пространстве, старые фото и завершённая задача сохраняются.

## Адверсариальное перечитывание

- Callback содержит действие, UUID и ограниченную положительную версию, помещается в лимит 64 байта. Отрицательные/нулевые/переполненные версии, неизвестное действие и неверный UUID отклоняются. Browser API не принимает внутренний Telegram-контекст: попытка даёт 400.
- Статус меняется в сериализуемой транзакции с проверкой текущего активного EMPLOYEE, организации, роли, UUID привязки, bot/user ID и исполнителя задачи. Чужой исполнитель/организация получают 404; отключённый сотрудник, смена роли и устаревшая после отвязки привязка — 403. Гонка с отвязкой до записи воспроизведена через processor: задача осталась TODO.
- TODO→DONE запрещён; после DONE старая Start-кнопка не возобновляет работу. Повтор подтверждает только непосредственно полученное состояние version+1: версия, аудит и уведомление не меняются. При другой версии выдаётся объяснение об устаревшей кнопке. Проверены последовательные и конкурентные повторы и изменение задачи владельцем между нажатием кнопок.
- Ошибка аудита откатывает статус. Двойное завершение даёт один переход, а выбранная для фото задача очищается в той же транзакции. Закрытая карточка своей задачи доступна только для чтения; список и очередь назначений по-прежнему требуют активную задачу. Повторные внешние сообщения Telegram остаются возможны при потере ответа; бизнес-переход не дублируется.
- Смена статуса задачи не завершает заказ, не публикует фотографии и не освобождает рабочую бронь. Защита от пересечений, точные деньги и даты не менялись; проверены регрессионные сценарии распределения, паспорта и команды. Сроки карточки остаются по Алматы. Фото закрытых задач недоступно, переназначение/отвязка при загрузке по-прежнему проверяются на записи.

## Проверки

Пройдены check:structure, typecheck, npm test (29 backend + 3 локализации), полная production build. Интеграции Telegram/team/scheduling/smart-orders: 37 успешных тестов Node runner, включая 4 родительских. Bot API заменён fake transport, PostgreSQL и транзакции реальные; данные создаются и удаляются только в собственных тестовых организациях. Прогоны выполнены на собранном API без watch с отключённой внешней почтой и Telegram. Существующее предупреждение pg о параллельном client.query не изменило результат, защитные лимиты не отключались.

Frontend не изменялся; новый сценарий взаимодействия проверен через реальные processor/service и моделируемые Telegram callbacks, а не через Edge. Автотест не выдаётся за нажатие кнопок физическим пользователем Telegram. Проверки не гарантируют безопасность или готовность к коммерческому запуску. Секреты, локальные сеансы, личные ссылки, тестовые изображения и .env исключаются из коммита.

После тестов восстановлен обычный dev:https с настройками .env. Новая TODO-задача версии 1 создана штатным API для ранее подключённого тестового сотрудника; реальная очередь получила SENT. Успешный polling подтверждён lastPollAt (возраст 9 секунд по UTC). Кнопки на физическом аккаунте пользователь может проверить на этой новой задаче; автоматическая проверка не меняла статус за него.
