# PostgreSQL на порту 5432

Текущий локальный профиль TirekCRM с 09.11.2026 использует установленный PostgreSQL 17.11 вместо переносимого PostgreSQL 18 на порту 54329. Изменение относится к этому компьютеру: секретный `.env` не отправляется в GitHub, остальные копии проекта автоматически не переключаются.

## Подключение

| Поле | Значение |
| --- | --- |
| Host | `127.0.0.1` |
| Port | `5432` |
| Database | `tirek` |
| Application user | `tirek` |
| Windows service | `postgresql-x64-17` |

Роль приложения владеет только новой базой `tirek`; у неё нет SUPERUSER, CREATEDB, CREATEROLE, REPLICATION, BYPASSRLS и членства в других ролях. Учётная запись администратора `postgres` использовалась только для создания отдельной роли и базы. Её настройки не изменены. Пароль роли приложения настроен локально; в отчёт и репозиторий не копируется.

В `.env` задан `DATABASE_URL` вида `postgresql://tirek:<URL_ENCODED_PASSWORD>@127.0.0.1:5432/tirek`. Пароль кодируется как часть URL. Другие параметры `.env`, включая Gmail и ключ шифрования почты, сохранены. Настройки приложения/API, порт HTTPS и учётные записи CRM остаются прежними.

Для pgAdmin зарегистрируйте сервер с Host/Port из таблицы, Maintenance database `tirek` и Username `tirek`; пароль вводится локально. Таблицы находятся в `Databases → tirek → Schemas → public → Tables`.

## Доступ к порту только с этого компьютера

16.11.2026 в конфигурации службы PostgreSQL 17 установлен `listen_addresses = 'localhost'` и выполнен перезапуск. На 5432 проверены только `127.0.0.1` и `::1`. Правила pg_hba.conf допускают SCRAM-аутентификацию с loopback. Клиент TirekCRM подтвердил подключение к базе после перезапуска. Ограничение относится к службе на этом компьютере.

Для описанной установки повторная настройка выполняется из PowerShell с правами администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\postgres-loopback.ps1
Get-NetTCPConnection -LocalPort 5432 -State Listen
```

Скрипт проверяет имя службы, каталог данных и слушающий процесс. Перед перезапуском он сохраняет резервную копию конфигурации рядом с `postgresql.conf`. Для установки с другим каталогом, службой или переопределениями конфигурацию проверяет администратор. [Параметр listen_addresses в PostgreSQL 17](https://www.postgresql.org/docs/17/runtime-config-connection.html)

## Запуск

Служба PostgreSQL настроена на автоматический запуск. Проверить её в PowerShell:

```powershell
Get-Service postgresql-x64-17
Test-NetConnection 127.0.0.1 -Port 5432
npm run db:migrate
npm run dev:https
```

Сайт — https://localhost:8443. Проверка API — https://localhost:8443/api/health; ответ `status: ok` включает реальный запрос к БД. `npm run db:local` для этого профиля не запускается: он обслуживает сохранённый переносимый кластер. `db:seed` после переноса не требуется. В новом терминале команды выполняют из каталога TirekCRM, где находится `package.json`.

## Что перенесено

Все 23 таблицы приложения: организации, пользователи, сеансы, клиенты, заказы/услуги, финансы, документы, задачи/комментарии, уведомления, почта, обращения, квитанции и паспорта/фото. Таблицы, где записей не было, также созданы. В целевой базе применены 15 штатных миграций; имена и контрольные суммы сверены с исходной историей `_prisma_migrations`.

Исходная схема — PostgreSQL 18, целевая — 17. Поэтому схема создана миграциями проекта, а данные перенесены [текстовым COPY](https://www.postgresql.org/docs/17/sql-copy.html) с явными столбцами. Исходный экспорт сделан в одной read-only Repeatable Read транзакции; загрузка — в одной транзакции в порядке внешних ключей, без отключения ограничений. После загрузки повторный упорядоченный экспорт каждой таблицы совпал с исходным SHA-256. Форматы DateStyle/UTF-8/UTC фиксированы на время копирования. История миграций в целевой базе создана Prisma, её служебные временные метки не переносятся.

Созданы локальные копии в `.local/backups/postgres-5432-<timestamp>/`: предыдущий `.env`, исходные COPY-файлы, manifest с количеством строк и хешами, а также нативный архив `tirek-postgresql17.dump`. Эти файлы содержат частные данные и исключены из Git. Исходный кластер `.local/postgres` сохранён и штатно остановлен. После начала работы на 5432 старый кластер и созданные копии являются снимками на момент переноса, а не синхронными копиями.

Для будущих резервных копий можно использовать pgAdmin → Backup базы `tirek`, формат Custom. Сохраняйте их в частном каталоге; очередную копию создают после новых изменений данных. Текущие резервные копии находятся на том же компьютере и не защищают от потери диска. Политика хранения, внешние копии и автоматическое расписание — отдельная задача.
