# Уведомления о задачах
Колокольчик в верхней панели доступен владельцу и сотруднику. Список и счётчик относятся только к текущему аккаунту. Доступные действия: показать непрочитанные, отметить одно уведомление или непрочитанные на текущей странице, открыть обсуждение задачи.

## Правила доставки
| Событие | Получатели |
| --- | --- |
| Создание задачи или смена исполнителя | Новый исполнитель, если он не автор действия |
| Фактический переход статуса | Активные владельцы компании и текущий исполнитель, кроме автора |
| Новый комментарий | Активные владельцы компании и текущий исполнитель, кроме автора |

Повтор комментария с тем же ключом, повтор публикации одного события и переход в уже установленный статус не создают новые уведомления. Редактирование названия/срока без переназначения, собственные действия и старые события до миграции не рассылаются. Напоминания о сроках, email и push пока не добавлены.

## Хранение и доступ
Notification связана с получателем и задачей составными ключами с organizationId. Публикация входит в Serializable-транзакцию исходного изменения и аудита: при отказе уведомлений действие не сохраняется частично. eventKey уникален в пределах организации и получателя: идентификатор комментария либо задача/тип/версия. Отдельная очередь не требуется для текущей записи внутри одной БД.

При каждом запросе список, счётчик и отметка прочтения повторно проверяют активность пользователя и текущую роль. Сотрудник видит уведомления только по назначенным ему задачам. Переназначение удаляет уведомления прежних исполнителей с ролью EMPLOYEE; дополнительная фильтрация по актуальной задаче защищает чтение даже при наличии старых строк. Владелец не получает доступ к личному списку другого пользователя.

Хранятся имя автора события, тип, статус на момент перехода, createdAt и readAt. Название задачи читается актуальное; текст комментария, финансовые данные, email и ключ события в DTO не включены. Имена/названия отображаются текстом. Дата в UI — Asia/Almaty.

## API
| Метод и путь | Вход | Ответ |
| --- | --- | --- |
| GET /api/notifications | page, pageSize (1–100), unread=true/false | items, total, pages, page, pageSize, unreadCount |
| GET /api/notifications/unread-count | Нет | unreadCount |
| POST /api/notifications/read | ids: 1–100 уникальных UUID | ok: true |

Неизвестные поля списка/тела записи запрещены. Для недоступного, чужого или несуществующего идентификатора read возвращает 404 и не меняет остальные строки. Повторное чтение идемпотентно, прежний readAt не переписывается. Групповая отметка передаёт явные идентификаторы показанных строк: более поздние события остаются непрочитанными. При конфликте транзакции ограниченно повторяются.

Ответы имеют Cache-Control: no-store. Запись требует допустимый Origin и сеанс. POST /read ограничен 60 запросами в минуту на IP; общий лимит API также действует. Изменения readAt не добавляются в бизнес-аудит: исходное событие уже записано в истории задачи.

## Интерфейс и ограничения
Счётчик и открытый список обновляются каждые 30 секунд в видимой вкладке, при возвращении к ней и вручную. Доставка внутри приложения не означает мгновенный push. Непрочитанных может быть больше, чем строк текущей страницы; значок показывает 99+ для больших значений.

Запоздавшие ответы предыдущей загрузки игнорируются. После 401 центр сначала проверяет актуальный сеанс: ответ от старой cookie после смены пароля не должен завершать новый вход. Реально отозванный сеанс возвращает на форму авторизации. Перед открытием обсуждения задача запрашивается заново; недоступная задача не открывается.

Пагинация использует смещение; новые события между переходами могут сдвигать страницы. Полученные ранее сведения нельзя отозвать с устройства. Запрос, выполняющийся одновременно с переназначением, может сериализоваться перед ним. Лимит IP разделяют пользователи одной сети; распределённый лимитер, сроки хранения и нагрузочное тестирование предстоят перед пилотом.

## Проверки
tests/notifications.integration.mjs запускает отдельный экземпляр обычного API на временном loopback-порту с неизменёнными лимитами, чтобы не расходовать IP-бюджет других наборов. БД общая локальная, данные ограничены собственными тестовыми организациями. Проверяется доставка, права, повторы, параллельное прочтение, пагинация, откат исходного действия, внешние ключи и 429/Retry-After.

tests/browser/notifications.spec.ts проверяет обе роли, RU/KK/EN, телефон, сетевые ошибки, устаревшие ответы, переназначение, смену и отзыв сеанса.
