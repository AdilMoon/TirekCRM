# Локализация
Поддерживаются ru (русский), kk (қазақша) и en (English). Для казахского используем языковой код kk, а не код страны kz. Форматирование: ru-KZ / kk-KZ / en-GB, валюта KZT, время Asia/Almaty.

Переводы находятся в frontend/i18n/messages.json. Ключ — исходная русская строка; значения kk и en обязательны. Используйте t('Ключ') и t('Заказ № {0}', number). Позиционные параметры должны совпадать во всех языках. Для дат и денег используйте dateLabel и formatMoney из useI18n.

Язык хранится в localStorage под tirek.locale и синхронизируется между вкладками. При недоступном хранилище переключатель работает до перезагрузки. Изменение языка обновляет lang документа, не пересоздаёт формы и не меняет пользовательские значения. На серверном рендере используется русский; после загрузки применяется сохранённый выбор. Предпочтение пока относится к браузеру, а не к учётной записи.

Серверные ошибки показываются через словарь. Ошибки схемы ввода имеют код VALIDATION_ERROR и общее переведённое сообщение. Не показываем пользователю необработанные исключения БД. Сообщения браузерной HTML-валидации зависят от языка самого браузера.

Печатные подписи акта доступны на трёх языках. Имена, услуги, адреса, комментарии и сохранённые снимки не переводятся автоматически. На старте используются вымышленные русскоязычные демо-данные.

Перед пилотом нужен редакторский просмотр казахских переводов и терминологии документов носителем языка. npm run check:structure проверяет полноту и параметры переводов; Playwright проверяет переключение, сохранение формы, ошибки и печатный акт.

Казахские месяцы и дни недели формируются явно: некоторые сборки ICU в браузерах показывают M10 вместо названия месяца. Преобразование в календарную дату выполняется для Asia/Almaty. Проверки: npm run test:i18n.
