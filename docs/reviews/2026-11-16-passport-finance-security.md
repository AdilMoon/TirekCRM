# Адверсариальное ревью: фотографии, CSV и локальный HTTPS

## QR-паспорт

- Старый обработчик загрузки принимал `shared` от любого пользователя с доступом к фото. При активной ссылке сотрудник мог изменить состав публичного паспорта через загрузку. Ограничение проверяется до декодирования и внутри транзакции записи. Интеграционный тест отправляет `shared:true` от назначенного сотрудника и получает 403. Для чтения сотрудника отбор фото по автору применяется в запросе БД, в UI передаётся общий счётчик для ограничения в шесть снимков.
- PATCH видимости проверяет сессию OWNER, Origin, строгие поля, организацию, заказ и фото. Проверены чужая организация, сотрудник, неверный Origin, неизвестное поле и отсутствующее фото. Повторы текущего состояния возвращают успех без новой версии или события. После скрытия устаревший запрос публикации даёт 409. Два параллельных запроса добавляют ровно одну версию. Ошибка аудита откатывает изменение, публичный ответ остаётся прежним.
- Скрытие сохраняет фото в CRM и исключает его из последующих публичных ответов. Изменение видимости повышает версию заказа и делает прежнюю отметку выполнения неактуальной. Уже полученные снимки могут оставаться в браузерах и локальных копиях. Заголовки `no-store` защищают ответы API от штатного кэширования.
- Подтверждение публикации в браузере относится к конкретному снимку и версии заказа. Нормальная загрузка из интерфейса и из Telegram приватная. Сохранена совместимость загрузки `shared:true` для OWNER через API. Ранее сохранённые флаги публикации проверяет владелец через карточку. При смене исполнителя доступ к старой задаче прекращается, а новый сотрудник видит только собственные фотографии.

## Финансы и интерфейс

- Кнопка экспортирует поиск, вид операции, категорию и даты без параметров страницы. Реальный CSV скачивается только при успешном ответе `text/csv`. JSON-ошибки, отказ API и неверный диапазон дат обработаны в интерфейсе. Браузерный тест проверил параметры, имя файла и точное значение 100.25. Серверные тесты отдельно проверили защиту от CSV-формул, границы организаций, лимиты и даты Алматы.
- Просмотрены снимки карты фото в Edge на настольном и мобильном размере. Загрузка, состояния видимости, обновление устаревшей карточки и удаление из публичного ответа проверены через HTTPS. Счётчик фотографий учитывает общую вместимость. Рабочий профиль явно описывает плановую доступность; фактическое рабочее время учитывает работодатель.

## Веб и окружение

- Next.js выдаёт запрет встраивания через CSP frame-ancestors и X-Frame-Options, ограничивает base-uri, object-src и form-action, исключает referrer и индексацию. Это политика отдельных директив, без контроля источников скриптов. Заголовки HTTP проверены в Edge, работа сессий и API — отдельными интеграциями.
- PostgreSQL 17 прослушивает 5432 на всех интерфейсах (`listen_addresses=*`), SSL PostgreSQL выключен, активные строки файла pg_hba.conf разрешают host-подключения только с loopback через SCRAM. Доступность порта с других машин в рамках этой проверки не измерялась. Для локальной установки ограничение самого слушателя до localhost требует изменения конфигурации службы администратором и её перезапуска. Служба может обслуживать и другие базы, поэтому изменение её конфигурации оставлено отдельной эксплуатационной задачей.
- Docker использует 8080 для другой локальной службы. Тестовый HTTPS запущен с `TIREK_HTTP_REDIRECT_PORT=8088`; проверены фиксированный редирект на 8443, TLS 1.2/1.3, отсутствие TLS 1.1, Origin и кэширование. Редиректовый порт проверяется перед передачей в Caddy. Исходное значение по умолчанию — 8080.

## Проверки и границы

Пройдены check:structure, typecheck, npm test (29 backend + 3 локализации), production build, тест локального HTTPS, 57 интеграционных проверок с родительскими тестами и 4 сценария Microsoft Edge. npm audit для production-зависимостей вернул 0 известных уязвимостей. При первом общем прогоне проверки исчерпали штатный лимит загрузки фото; повтор Edge прошёл после обновления окна. Проверка устаревшей карточки теперь ожидает 409 и обновляет данные, а проверка CSV локализует уведомление об ошибке. Тесты изменяли только собственные организации, почта и Telegram работали в тестовых режимах.

[Матрица правовой готовности](../pilot-readiness-kz.md) охватывает текущий сценарий в Казахстане. Для внешнего запуска остаются вопросы оператора, размещения, законных оснований и сроков хранения, внешних провайдеров, отраслевых требований и применимости правил оформления документов. Успешные проверки подтверждают перечисленные сценарии.
