# Заказы, требующие внимания

Откройте «Заказы → Требуют внимания» или нажмите «Все причины по заказам» на главной странице.

Владелец видит активные заказы и незакрытые вопросы по завершённым работам. Завершённая работа остаётся в обзоре при непроверенных чеках, часах на проверке, незаданных ставках по подтверждённому труду или вопросах по связанному выезду.

## Причины и переходы

| Причина | Условие | Раздел |
| --- | --- | --- |
| Прогноз убытка | Полный прогноз прибыли отрицателен | Прибыльность исходного заказа |
| Не хватает данных | Для расчёта труда или оставшихся расходов нужны данные | Прибыльность соответствующей работы |
| Чеки на проверке | Есть PENDING-чеки | Прибыльность и рассмотрение чека |
| Срок согласования истёк | Открытый заказ имеет истёкшую ссылку без согласования или отзыва | Смета и допработы |
| Перерасход времени | Подтверждённые минуты превышают заданный план | План и факт |
| Часы на проверке | Есть отправленные на проверку рабочие минуты | План и факт, затем решение в табеле |
| Срок заказа прошёл | Дата срока открытого заказа раньше текущего дня в Алматы | Карточка и редактирование заказа |
| Повторное обращение клиента | Есть открытый запрос обслуживания из QR-паспорта | Объект, история и решение по обращению |

Исходный заказ занимает одну строку. Причина, относящаяся к выезду, содержит его номер и открывает сам выезд. В строке показаны фактическая и прогнозная прибыль. Неизвестный результат отображается как неполный расчёт.

Сводка и счётчики причин учитывают поиск по всем причинам. Фильтр причины меняет список. Один заказ может иметь несколько причин, поэтому сумма счётчиков причин может превышать количество заказов. Прогноз убытка в сводке суммирует известные отрицательные результаты исходных заказов. Сначала показаны наиболее крупные известные убытки, затем остальные заказы по номеру.

После закрытия карточки список обновляется и возвращается на первую страницу. Подтверждённый чек исчезает из причин проверки, новая ссылка убирает истёкшее согласование, а заполненная ставка пересчитывает прибыль.

## Расчёт и доступ

Карточка прибыльности и обзор используют общий расчёт и загрузчик данных. Он учитывает подтверждённые часы, индивидуальные ставки, часы на проверке в прогнозе, расходы за вычетом сторнирований, складские выдачи и возвраты, а также затраты повторных выездов.

Отчёт читается в одной транзакции REPEATABLE READ. Заказы обрабатываются пакетами по 100, в ответе выдаётся 20 строк. Фильтры и сводка охватывают всю выбранную область. Обзор пересчитывается при запросе. Время снимка возвращается в asOf.

GET /api/orders/attention доступен активному владельцу своей организации. Поиск ограничен 160 символами, причина выбирается из фиксированного перечня. Лимит тяжёлого отчёта составляет 60 запросов в минуту на сеанс. Ключ лимита — хеш сеанса. На чтение установлен тайм-аут 20 секунд.

Историю завершённых заказов можно открыть в обычном списке и карточках прибыльности. Новый обзор предназначен для текущих решений.
