# Адверсариальное ревью: история и оплаты клиента

Дата: 25 ноября 2026. После реализации отдельно перечитаны контроллер, SQL, контракт ответа, фильтры, переходы модального окна и стили. Проверки не меняли рабочие данные: использовались собственные тестовые организации в отдельной QA-базе.

## Выявленные проблемы и проверенные предположения

1. **Длинные контакты сжимали кнопку.** Визуальный просмотр реального PNG из Edge воспроизвёл кнопку «Редактировать клиента», разбитую на узкие фрагменты по несколько букв. Исправлены flex-параметры текстового блока и кнопки; контакты переносятся, кнопка сохраняет читаемую ширину. Уточнено горизонтальное размещение чекбокса фильтра.
2. **Скриншот мобильной карточки после проверки фокуса показывал только конец списка.** Shift+Tab правильно переводил фокус с закрытия на последнюю кнопку, прокручивая диалог. Снимок верхней части перенесён перед проверкой фокуса; сама проверка удержания фокуса осталась.
3. **Сумма `стоимость − оплаты` могла бы скрыть остаток другого заказа за переплатой.** Вместо общей разницы суммируются положительные остатки каждого заказа. Интеграционный тест включает переплату на один тиын и подтверждает отсутствие взаимозачёта между заказами.
4. **Несколько платежей и возвратов могли бы умножиться при JOIN.** Возвраты агрегируются по платежу до агрегации платежей по заказу. Проверено на нескольких платежах и возвратах: чистая оплата `39.99`, остаток `60.02`.
5. **Контакты и сводка могли бы относиться к разным моментам времени.** Реальный конкурентный тест изменяет имя клиента и добавляет заказ между первым чтением и агрегатом. RepeatableRead возвращает старые контакты со старой сводкой; следующий запрос видит оба изменения. Фильтры и пагинация не меняют общую сводку.
6. **Строки клиента могли бы остаться на экране после потери доступа.** Edge воспроизводит 503, восстановление и смену роли владельца на сотрудника: после ошибки нет прежнего имени, контактов и строк; 403 отображается в карточке. Повтор не создаёт записей, это read-only маршрут.
7. **Повтор ключа перевода.** При добавлении словаря обнаружен уже существующий ключ «Редактировать клиента». Новая дублирующая запись удалена, применяется исходный перевод.

## Границы и данные

- Реальный HTTP: 401 без сессии, 403 сотруднику, 404 другому владельцу и при попытке открыть чужого клиента своим токеном. `organizationId` и `unpaid=false` отклоняются строгой схемой. Маршрут принимает UUID через ParseUUIDPipe и ограничен по частоте запросов.
- Все чтения ограничены организацией и конкретным clientId. Одноимённый клиент другой организации и другой клиент своей организации не попадают в сводку. Параметры SQL не конкатенируются с пользовательскими значениями. Поиск `x' OR 1=1 --` и `%` не расширяет выборку.
- Контакты, названия и компания выводятся как текст React. Проверены длинные строки и `<script>` без создания script/img. Из контактов не генерируются непроверенные URL.
- Проверены 108 заказов плюс конкурентное добавление 109-го, клиент без заказов, отменённый заказ, завершённый, бесплатный повторный выезд, возвраты, полная и избыточная оплата, фильтры, шесть страниц и страница за концом выборки. Число SQL-вызовов ограничено и не растёт с числом заказов.
- Итоги `30000000000010301.00` и `30000000000010060.99` проходят точно, без Number для денег. Версия клиента возвращается для существующего оптимистического редактирования. Переход к заказу использует защищённый API; запись оплаты и её идемпотентность не менялись.

## Результаты проверок

- PostgreSQL-интеграция: пройден тест с 108 заказами и конкурентным добавлением 109-го, проверкой точных сумм, изоляции чтения, областей клиентов/организаций и пустых выборок.
- Microsoft Edge: 6/6 сценариев — карточка клиента (3) и регрессия рабочего пространства (3). Финальный прогон после исправления стилей пройден; PNG настольной и мобильной карточки просмотрены.
- `npm test`: 29 backend + 3 localization проверки пройдены. `check:structure`: 1184 записи переводов и границы модулей. `npm audit --omit=dev --audit-level=low`: 0 известных уязвимостей на момент проверки.
- Native и Docker production build успешны. HTTPS health 200, карточка клиента без сессии 401, внешний маршрут внутренних метрик 404. Контрольные хеши рабочих заказов, клиентов, организаций и задач, количество пользователей/фото и суммы оплат/расходов до и после обновления совпали.

## Ограничения

Сводка не является историческим регистром, использует текущие связи/стоимость заказов. Не добавлены автоматический взаимозачёт, банковская сверка и внешние уведомления. При поиске/обновлении данные временно заменяются состоянием загрузки; автоматического фонового обновления нет. Проверка 108 заказов не заменяет нагрузочное испытание больших организаций. Успешные проверки не гарантируют безопасность или коммерческую готовность.
