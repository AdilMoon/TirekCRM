# Учёт фактически отработанного времени

В разделе «Табель» сотрудник видит свои интервалы. Он выбирает фактическое начало и окончание работы по Алматы и отправляет запись на проверку. Владелец видит записи компании, может указать время за активного сотрудника и принять решение. Перерывы, исключённые из рабочего времени по правилам работодателя, оставляют между интервалами.

1. **На проверке.** Запись учитывается в ожидающих минутах месяца.
2. **Подтверждена.** Запись добавляется к подтверждённому времени.
3. **Отклонена или аннулирована.** Владелец указывает причину. Исходный интервал сохраняется, а его минуты исключаются из итогов. При необходимости сотрудник или владелец отправляет новый исправленный интервал.

Месяц и сотрудник определяют сводку. Фильтр статуса ограничивает список, сохраняя обе цифры в сводке. Для смены через границу месяца каждый месяц получает только свою часть минут. Карточка интервала показывает его полную длительность. Записи имеют точность до минуты, интервал может длиться от 1 минуты до 24 часов. Будущее время отклоняется. Приложение допускает соседние интервалы и отклоняет пересечения записей на проверке или подтверждённых записей одного сотрудника. График назначений и статусы задач используются в собственных рабочих процессах.

## API

| Маршрут | Доступ и данные |
| --- | --- |
| `GET /api/work-time?month=YYYY-MM` | OWNER своей компании или EMPLOYEE только за себя. Дополнительно `status`, `page`; фильтр `employeeId` доступен OWNER. |
| `GET /api/work-time/people` | OWNER. ID, имя и состояние доступа сотрудников своей компании. |
| `POST /api/work-time` | Начало и конец в ISO 8601 с часовым поясом, `idempotencyKey`. OWNER указывает `employeeId`, EMPLOYEE определяется по сессии. Подтверждение выполняется отдельным действием. |
| `PATCH /api/work-time/:id/decision` | OWNER. Статус и `version`. Для отклонения и аннулирования обязательна `note`. После аннулирования исправление создаётся отдельной записью. |

Изменения статуса и аудит сохраняются вместе. Повтор идентичной отправки возвращает существующую запись. При конкурирующих изменениях решение опирается на версию. PostgreSQL проверяет связи с компанией и запрещает пересечения через EXCLUDE. История действий доступна владельцу через фильтр «Табель».

## Границы учёта

Табель отражает сообщённые интервалы и решение владельца. Само присутствие на рабочем месте подтверждается процессом работодателя. Статья 79 Трудового кодекса РК также предусматривает учёт неотработанного времени и отдельных видов времени, включая сверхурочные, ночные часы, выходные, праздники и командировки. Форму и порядок учёта определяет акт работодателя. Для использования с реальными трудовыми данными нужно определить эти категории, доступ, хранение и порядок исправления. [Трудовой кодекс РК](https://old.adilet.zan.kz/rus/docs/K1500000414)

Следующие шаги для этого модуля: категории по режиму работы и календарю работодателя, экспорт утверждённого месяца и история его закрытия, уведомления о решении в CRM и, при допустимости передачи, через Telegram. Зарплатные расчёты требуют отдельно утверждённых правил начисления.
