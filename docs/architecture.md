# Архитектура и размещение файлов
Используем монорепозиторий npm workspaces и модульный сервер NestJS. Фронтенд работает с сервером через HTTP /api. Логика денег и разграничение организаций выполняются на сервере.

## Ответственность каталогов

| --- | --- |

| backend/src/modules/crm | HTTP-контроллер, SearchService и бизнес-операции CRM |
| backend/src/auth | AuthModule/AuthService: вход/выход, смена пароля, отзыв сеансов; SessionGuard и Origin |
| backend/src/modules/mail | Транзакционная очередь уведомлений аккаунта, локальный/Gmail транспорт, обработчик доставки |

## Правила
1. UI не импортирует backend. Backend не импортирует frontend. Контракты не зависят от приложений.
2. Контроллер валидирует запрос и передаёт работу сервису. Не добавляем обработку БД в UI.
3. organizationId берётся из сессии. Каждая операция чтения и записи ограничена организацией.
4. Миграции коммитятся; ручное изменение рабочей БД не заменяет миграцию.
5. Не используем JS Number для финансовых проводок. Денежные значения в API — строки; расчёт — bigint в тиынах; БД — NUMERIC.
6. Новые экранные строки проходят через t(). Пользовательские значения не переводятся.
7. Тестовые данные удаляются только в тестовых организациях. Генерируемые файлы и секреты исключены из Git.
8. Новые самостоятельные серверные области выделяем в backend/src/modules/<domain>. Общий crm.service пока содержит существующий небольшой набор операций.
9. Настоящие вложения и документы нельзя складывать в исходники frontend/public; хранилище подключим отдельным адаптером.
10. Проверка npm run check:structure проверяет основные папки, прямые зависимости между приложениями, статические строки JSX и полноту словаря. Это дополнение к ревью, не полный анализ архитектуры.

## Данные документов
Изменение клиента или компании применяется к будущим актам. Созданный акт хранит снимок исходных реквизитов и услуг. Смена языка изменяет подписи интерфейса документа; сохранённые пользовательские данные остаются прежними.

## Командная работа
Подробная [матрица прав и API](team-and-tasks.md). Сотрудник видит отдельное рабочее пространство задач. Права на каждом защищённом маршруте проверяет SessionGuard; чтение и изменение задач дополнительно ограничены организацией и исполнителем.

По запросу пользователя после каждой итерации проводится адверсариальное ревью. Правило закреплено в AGENTS.md; результаты и воспроизводимые дефекты — в docs/reviews/.

Управление собственным аккаунтом доступно обеим ролям через frontend/features/account-security.tsx. Запись аудита выделена в AuditWriterModule, чтобы AuthModule мог записывать события без циклического импорта. Контракты и ограничения описаны в [account-security.md](account-security.md).

Создание компании — отдельный OnboardingModule. Он использует существующие таблицы, общий выпуск сеансов и AuditWriterModule. Интерфейс регистрации — frontend/features/register-company.tsx, маршрут /register; подсказки пустого пространства — frontend/features/getting-started.tsx. Подробности — [company-onboarding.md](company-onboarding.md).

Обсуждения задач находятся в backend/src/modules/tasks/task-comments.service.ts и frontend/features/task-discussion.tsx. Таблица TaskComment связана с задачей и автором составными ключами организации; правила доступа и идемпотентности — в [task-discussions.md](task-discussions.md).

Центр уведомлений — frontend/features/notifications.tsx, подключён к обеим рабочим областям. NotificationWriter — функция с явным TransactionClient, поэтому публикация не создаёт вложенную транзакцию и не требует циклического импорта модулей. Описание — [notifications.md](notifications.md).

Адаптивная навигация владельца выделена в frontend/components/workspace-navigation.tsx; мобильные переопределения стилей — frontend/app/mobile.css. Подробности — [мобильное рабочее пространство](mobile-workspace.md).

Реестр обращений — отдельный PrivacyRequestsModule и компоненты frontend/features/privacy-requests.tsx / privacy-request-forms.tsx. Правила доступа, повторов и ограничения — в [privacy-requests.md](privacy-requests.md).

Чистая оплаченная сумма вычисляется в backend/src/common/paid.ts. Отчёты, обзор и совместимый /movements используют modules/finance/ledger.ts; форма операций — frontend/features/financial-operation.tsx. [Правила финансовых корректировок](finance-adjustments.md).
