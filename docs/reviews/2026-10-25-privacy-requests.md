# Адверсариальное ревью: реестр обращений по персональным данным

Дата: 25.10.2026. Область: новый модуль NestJS, две таблицы и миграция, контракты, настройки владельца, история, RU/KK/EN. Изменения отдельно перечитаны после реализации; проверены предположения о доступе, повторах, атомарности, датах и отображении недоверенного ввода. Независимый внешний аудит не проводился.

## Попытки опровергнуть корректность

| Риск | Проверка и наблюдаемый результат |
| --- | --- |
| Чужая компания / сотрудник / подмена организации | Две тестовые организации, OWNER/EMPLOYEE: списки изолированы; чужая карточка и PATCH — 404, сотрудник — 403, отсутствие сеанса — 401; поля organizationId/createdById/status в создании отклонены |

| Три параллельные регистрации | Один id, одна запись и одно событие. Верхний регистр UUID не создаёт новый ключ; изменённый ввод с тем же ключом — 409 |

| Подтверждение из другой организации | Прямая попытка связать чужой organizationId с обращением отклонена составным внешним ключом |

| Устаревшая карточка | Внешнее закрытие перед отправкой из старой карточки даёт 409; после открытия заново виден сохранённый результат |

| Непреднамеренное удаление / деньги | Закрытие обращения DELETION не меняет тестового клиента и не создаёт заказ/платёж; денежная арифметика не затрагивалась, существующие финансовые регрессии входят в общий API-прогон |

## Исправления и уточнения по проверкам

- Повторы изменений реализованы через отдельные подтверждения, а не только последний ключ в карточке: иначе давний принятый запрос после следующего перехода нельзя было бы уверенно распознать. Воспроизводимый регрессионный сценарий повторяет IN_PROGRESS после закрытия и проверяет текущее состояние.
- Полный текст и контакт исключены из DTO списка; карточка получает их отдельным защищённым запросом. На 401/403/404 изменения уже загруженные подробности очищаются.
- Исправлен порядок браузерной проверки отзыва прав: первый вариант менял роль до завершения обновления списка, вследствие чего проверяемая кнопка уже исчезала. Теперь роль меняется при запросе карточки; отдельный сценарий отзывает её после фактического открытия. Это исправление тестовой гонки, а не найденный обход авторизации.
- Очистка API-тестов удаляет созданных ими клиентов в finally, чтобы сбой проверки не оставлял тестовую организацию. Данные вне собственных тестовых организаций не изменялись.

## Оставшиеся ограничения

Внешний пилот не разрешён этой итерацией: оператор и размещение не определены, реестр оснований/согласий и правила хранения ещё не реализованы. Срок ответа выбирается вручную; юридическая применимость и календарь не автоматизированы. Нет отправки ответа, проверки личности, экспорта/удаления по запросу, редактирования исходных полей и повторного открытия.

Ключ UI сохраняется только пока открыта форма: закрытие после неопределённого ответа требует проверки реестра перед новой регистрацией. Изменение роли не удаляет мгновенно уже увиденные сведения без следующего запроса; сервер проверяет доступ на каждом обращении. Просрочка обновляется при чтении, фоновых уведомлений нет. Список использует offset и contains/ILIKE; массовые данные, нагрузка и реальный телефон с экранной клавиатурой не исследованы. Проверка на эмуляции Edge не заменяет тест реальных устройств и ревью носителем казахского языка.

Успешные тесты подтверждают проверенные сценарии, а не гарантируют безопасность или готовность к коммерческому запуску. Остальные условия — в [матрице пилота](../pilot-readiness-kz.md).
