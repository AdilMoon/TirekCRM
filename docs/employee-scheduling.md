# Умное распределение сотрудников

## Как пользоваться

1. Владелец приглашает сотрудников в разделе «Команда». В «Навыки и график» задаёт каждому навыки через запятую, рабочие дни и одну смену для выбранных дней. Часы — по Алматы; конец `00:00` означает полночь. Пустые рабочие дни делают сотрудника недоступным.
2. В карточке заказа открывает «Умное распределение», указывает начало, длительность и нужные навыки, нажимает «Подобрать исполнителей». До подтверждения задачи и резервы не создаются.
3. Просматривает объяснения и выбирает подходящего сотрудника. Подтверждение резервирует время, создаёт связанную задачу, внутреннее уведомление исполнителю и аудит одной транзакцией. Сотрудник видит точное время в «Задачах» и может открыть фото заказа через существующий паспорт.
4. Через тот же экран можно изменить время/исполнителя или отменить назначение. При переназначении прежний резерв освобождается, прежняя задача отменяется, новая задача назначается выбранному сотруднику. Отмена или завершение самого заказа также освобождает резерв и переводит связанную задачу в CANCELLED/DONE.

На один заказ — одно текущее назначение и один ответственный EMPLOYEE. Сотрудникам недоступны подбор, профили коллег и изменение назначения. Владелец не участвует в списке исполнителей. Если сотрудников ещё нет, интерфейс предлагает пригласить их, без создания вымышленных сотрудников и графиков.

## Объяснение рекомендации

Это детерминированный подбор по явным правилам, без внешней модели и вымышленных процентов уверенности:

- Обязательны активный аккаунт, настроенный профиль, все требуемые навыки, рабочий день/смена на весь интервал и отсутствие пересечения с другим зарезервированным заказом.
- Среди подходящих сначала выбирается меньшая сумма зарезервированных минут в выбранный день, затем меньше незавершённых TODO/IN_PROGRESS задач. При равенстве — имя и UUID, чтобы порядок был стабильным.
- Для каждого видны занятые минуты, активные задачи и конкретные причины недоступности: отключённый доступ, отсутствие профиля, недостающие навыки, время вне смены, пересечение. Рекомендуемый кандидат отмечен; владелец может выбрать любого подходящего.
- Навыки сравниваются по точным названиям после удаления краевых пробелов и перевода в нижний регистр. Синонимы и перевод названий автоматически не выполняются: «окна» и «мытьё окон» — разные навыки. Пустые требования означают отсутствие требований к навыкам.

Подбор не изменяет график компании автоматически и не заявляет глобальную оптимальность. Если подходящих сотрудников нет, требуется изменить время, требования или настроить профили.

## Время, повторы и защита

Начало — в будущем в пределах 90 дней, шаг 15 минут; длительность 15–720 минут, работа внутри одного календарного дня Алматы и не позже даты срока заказа. Нельзя перенести срок заказа раньше уже назначенной работы. Время в API передаётся с явным смещением; в новых столбцах БД хранятся UTC timestamp, как в остальных DateTime проекта. Форматирование и проверка рабочих дней выполняются в Asia/Almaty, независимо от часового пояса Windows/PostgreSQL.

Два интервала пересекаются, если начало каждого раньше конца другого. Полуоткрытый диапазон `[начало, конец)` позволяет одному заказу закончиться в 10:00, а следующему начаться в 10:00. PostgreSQL EXCLUDE USING GiST запрещает пересечение для одного employeeId непосредственно при записи, включая конкурентные запросы. Используется штатное [btree_gist](https://www.postgresql.org/docs/17/btree-gist.html), доступное роли с CREATE на своей базе; права суперпользователя приложению не добавлялись. Partial UNIQUE разрешает только один неосвобождённый резерв на заказ. Составные FK сохраняют границы организации для заказа, исполнителя и задачи.

Подтверждение выполняется в Serializable-транзакции, повторно проверяет активного владельца, версию заказа/профиля, текущее назначение, навыки, график и конфликты. Ключ повтора связан с организацией, автором, заказом и хешем всего запроса. Потеря ответа не создаёт вторую задачу; интерфейс сохраняет неизменный запрос до определённого результата. Изменившееся расписание даёт 409 и требует нового подбора. Ошибка аудита/уведомления откатывает всю операцию, включая освобождение прежнего назначения.

Редактирование связанной задачи не может подменить исполнителя или заказ действующего резерва. Отменять резерв нужно через карточку заказа; отменённую задачу назначения нельзя повторно активировать обычным переходом статуса. DONE у задачи сам по себе не освобождает запланированное время: это делает владелец через заказ/отмену назначения. Профиль нельзя изменить так, чтобы уже назначенные будущие/текущие работы перестали соответствовать навыкам или графику. Отключение доступа сотруднику сохраняет резервы для явного решения владельца.

## API

Все маршруты требуют OWNER, своей организации и прежней Origin-защиты для записей:

| Метод и маршрут | Действие |
| --- | --- |
| GET `/api/scheduling/members` | Сотрудники и рабочие профили, без email/паролей |
| PATCH `/api/scheduling/members/:id` | Навыки, дни, минуты начала/конца смены, ожидаемая version (0 при создании) |
| GET `/api/orders/:id/assignment` | Версия/статус заказа и текущее назначение |
| POST `/api/orders/:id/assignment/recommendations` | startsAt, durationMinutes, requiredSkills; рекомендации без записи |
| POST `/api/orders/:id/assignment` | Интервал/навыки, employeeId, profileVersion, orderVersion, currentBookingId, idempotencyKey |
| POST `/api/orders/:id/assignment/cancel` | bookingId; повтор отмены именно этого назначения безопасен |

## Проверки и ограничения

```powershell
npm run check:structure
npm run typecheck
npm test
npm run build
# При запущенных БД и API, тестовая почта local
$env:WEB_ORIGIN='https://localhost:8443'
node --test tests/scheduling.integration.mjs
# Microsoft Edge, запущенный HTTPS, доверенный локальный CA
$env:NODE_EXTRA_CA_CERTS=(Resolve-Path '.local/caddy/pki/authorities/local/root.crt').Path
$env:TEST_WEB_URL='https://localhost:8443'
$env:PLAYWRIGHT_CHANNEL='msedge'
npx playwright test tests/browser/scheduling.spec.ts
```

В первой версии нет времени дороги, перерывов, отпусков/исключений по отдельным датам, внешних календарей, бригад, подбора альтернативного часа или контроля фактического опоздания. Обычные задачи без точного времени учитываются в количестве активных задач, но не блокируют интервал. По окончании зарезервированного времени следующая работа может начаться; фактическое продление требует переноса назначения владельцем. Подбор ограничен 200 сотрудниками компании. Тесты используют собственные организации и очищают только их. Telegram в эту итерацию не подключается.
