# Обсуждения задач
В разделе «Задачи» кнопка «Обсуждение» открывает историю договорённостей. Владелец видит задачи своей компании, сотрудник — только назначенные ему. Доступ проверяется на сервере при каждом чтении и отправке.

## Поведение
- Комментарий: от 1 до 2000 символов после удаления пробелов по краям; переносы строк сохраняются. HTML отображается текстом.
- История доступна текущему исполнителю целиком, в том числе после переназначения. Прежний исполнитель теряет доступ; уже полученный им текст невозможно отозвать с устройства.
- Автор и его имя берутся с сервера. Снимок имени остаётся прежним после переименования аккаунта. Время создаёт БД, интерфейс отображает его в Asia/Almaty.
- Новые сообщения сверху, по 20 на странице; есть ручное обновление. Сообщения не изменяют версию задачи.
- Текст неизменяемый через API; правки оформляются следующим комментарием. Вложения, редактирование, удаление и автоматическое обновление истории пока отсутствуют. Новые комментарии создают [личные уведомления](notifications.md) для других активных участников.
- При ошибке отправки введённый текст сохраняется в открытом диалоге. После сетевой ошибки или ответа 5xx текст блокируется; кнопка «Повторить отправку» отправляет исходное тело с тем же ключом. Последующий 429 не сбрасывает эту защиту. При однозначном отказе до неопределенного результата текст можно исправить. После закрытия диалога или перезагрузки черновик и ключ не сохраняются.
- При отказе в доступе история скрывается, отправка блокируется. При истечении сеанса применяется существующий возврат на вход.

## API
| Метод и путь | Данные | Результат |
| --- | --- | --- |
| GET /api/tasks/:id/comments | page, pageSize от 1 до 100 (по умолчанию 20) | items, total, page, pageSize, pages |
| POST /api/tasks/:id/comments | body, idempotencyKey (UUID) | Сохранённый комментарий, 201; одинаковый повтор возвращает ту же запись |

DTO комментария: id, body, authorId, authorName, createdAt. Неизвестные поля запрещены. Нет доступа к задаче — 404; нет сеанса — 401; неверный Origin — 403; невалидный ввод — 400; тот же ключ для другого текста или задачи — 409. POST ограничен 30 запросами в минуту на IP; общий ограничитель API также действует. Ответы с комментариями помечены Cache-Control: no-store.

Ключ уникален в пределах организации и автора. Проверка доступа выполняется до поиска ранее отправленного комментария, поэтому ключ не позволяет обойти переназначение. Проверка пользователя, задачи, запись комментария и аудит выполняются в Serializable-транзакции с ограниченным повтором конфликтов. GET использует RepeatableRead для единого снимка прав, строк и количества. Запрос, уже выполняющийся одновременно с переназначением, может упорядочиться перед ним; последующие запросы прежнего исполнителя отклоняются.

Составные внешние ключи TaskComment → BusinessTask и User включают organizationId. Новая миграция не удаляет и не перезаписывает существующие записи. Аудит TASK_COMMENT_ADDED содержит идентификатор комментария, без копии текста.

## Проверки
tests/task-comments.integration.mjs проверяет владельца/исполнителя, чужие организации, подмену автора, повторные и параллельные отправки, пагинацию, снимок имени, входные данные и составные связи БД. tests/browser/task-discussion.spec.ts проверяет потерю ответа после сохранения, повтор, текстовый HTML, языки, телефон и потерю доступа при переназначении.
