# Ревью локального запуска в Docker

- Docker-профиль публикует только HTTPS на loopback. PostgreSQL и контейнер миграций размещены во внутренней сети. API и интерфейс доступны прокси по именам сервисов. Origin для cookie и проверки запросов настроен на внешний HTTPS-адрес Compose.
- PostgreSQL использует отдельный том и собственные сгенерированные пароли для административной роли и роли приложения. Миграции выполняются ролью приложения, которой принадлежит база. Пароли и TLS-ключи не входят в контекст сборки. Профиль выключает доставку почты и Telegram по умолчанию, чтобы пустая копия CRM могла работать рядом с обычной.
- API ждёт успешного выполнения миграций. Caddy ждёт готовности API и Next.js. Проверка API обращается к PostgreSQL. Внешний адрес и том PostgreSQL отделены от обычного профиля `dev:https`.

## Результаты

- При первой сборке скачивание зависимостей в контейнере прерывалось с `ECONNRESET`. После снижения параллелизма и повторного запуска сборка с исходным lockfile успешно завершилась на Linux, включая генерацию Prisma, проверку типов и сборку Next.js. Прошли check:structure, 29 проверок API внутри образа и 3 проверки локализации. Образ запускается от непривилегированного пользователя, загружает Linux-сборку Sharp и не содержит локальные файлы конфигурации.
- Применены 24 миграции. В Windows импортирован проверенный локальный CA Docker. Microsoft Edge открыл регистрацию по HTTPS. Проверены регистрация компании, флаги Secure и HttpOnly, отказ для чужого Origin и запросов без сессии, создание заказа и ответ API прибыльности.
- Контейнер PostgreSQL пересоздан с тем же томом. Заказ и сессия сохранились, тестовая компания удалена после проверки. Только Caddy публикует порт. Роль приложения проверена на отсутствие прав суперпользователя, создания других ролей и баз. Обычный профиль на 8443 отвечал параллельно. Docker использует свою базу и свой сертификат.
