# Команда, приглашения и задачи

## Доступ
| Возможность | Владелец (OWNER) | Сотрудник (EMPLOYEE) |
| --- | --- | --- |
| Клиенты, заказы, финансы, акты, настройки | Все данные своей компании | Нет доступа |
| Общий журнал, список команды и приглашения | Доступны | Недоступны |
| Создание, описание, срок и переназначение задачи | Разрешены | Недоступны |
| Просмотр задач | Все задачи своей компании | Только назначенные ему |
| Статус задачи | Любой из четырёх, включая повторное открытие | TODO → IN_PROGRESS; IN_PROGRESS → TODO или DONE |
| Профиль и выход | Доступны | Доступны |

SessionGuard проверяет свежую роль и isActive при каждом запросе. На защищённых им маршрутах по умолчанию требуется OWNER; EmployeeAccess явно разрешает сотрудникам профиль, выход и операции чтения/статуса задач. Списки и отдельные задачи дополнительно ограничены assigneeId из сессии. Параметр assigneeId от сотрудника не расширяет его область доступа. Чужие задачи возвращают 404, закрытые разделы — 403. В интерфейсе сотрудника не запрашивается обзор или другие разделы владельца.

Сотрудник получает только название/описание задачи, срок, статус, версию, имя исполнителя и краткую связь заказа {id, number, title}. Владелец должен учитывать видимость текста поручения и названия заказа при назначении. Клиентские контакты, суммы, позиции заказа и его примечания не входят в DTO задачи.

Отключение сотрудника удаляет его сессии, блокирует новый вход и записывается в журнал. Следующий запрос старого сеанса получает 401. Уже показанные на экране данные не могут быть отозваны задним числом. Возврат доступа требует нового входа. Задачи остаются в компании и могут быть переназначены владельцем. Назначение на неактивного сотрудника запрещено. Отключить владельца через API команды нельзя.

## Приглашение
1. Владелец вводит имя и email в «Команда».
2. Сервер создаёт случайный секрет из 32 байт, сохраняет SHA-256 и срок 48 часов.
3. UI показывает одноразовую ссылку /join#token=… только в момент создания. Секрет не включён в выдачу команды и аудит; fragment не отправляется в URL HTTP-запроса. Для проверки и принятия UI передаёт его в теле POST.
4. Владелец копирует ссылку и лично передаёт адресату. Отправка писем не подключена.
5. Сотрудник видит компанию и email, задаёт пароль (12–128 символов), принимает приглашение и входит.
6. Принятие, создание EMPLOYEE и аудит выполняются одной Serializable-транзакцией. Одновременное повторное принятие даёт только один аккаунт; отозванные, истёкшие и использованные ссылки недействительны.

Секрет — средство доступа: получивший ссылку может принять приглашение. Проверки владения email ещё нет. Публичные POST также проверяют Origin и ограничивают частоту. Пароль хешируется scrypt. Email уникален для всей системы; присоединение существующего аккаунта к другой компании пока не поддерживается. Новое приглашение с тем же email в компании возможно после истечения или отзыва прежнего.

## API
Все пути начинаются с /api. Ответы не содержат passwordHash/tokenHash.

| Метод и путь | Вход и результат |
| --- | --- |
| GET /team | {members, invitations}; приглашения только ожидающие и неистёкшие |
| POST /team/invitations | {name,email}; приглашение и token, показанный один раз |
| POST /team/invitations/:id/revoke | Отзыв; повторный отзыв допустим, принятое не отзывается |
| PATCH /team/members/:id | {isActive,version}; сотрудник и новая версия |
| POST /team/invitations/preview | Публичный {token}; имя, email, компания, срок |
| POST /team/invitations/accept | Публичный {token,password}; создаёт EMPLOYEE, не входит автоматически |
| GET /tasks | q, status, assigneeId, orderId, page, pageSize; стандартная выдача страницы |
| GET /tasks/:id | Доступная пользователю задача |
| POST /tasks | {title,description,assigneeId,orderId?,dueDate?} |
| PATCH /tasks/:id | Полная форма задачи плюс version |
| PATCH /tasks/:id/status | {status,version} |

description по умолчанию пустое; orderId/dueDate могут быть null. Название: 1–200 символов, описание: до 2000. Дата — YYYY-MM-DD, хранится как DATE. Статусы TODO, IN_PROGRESS, DONE, CANCELLED. Изменение задачи/статуса увеличивает version; устаревшая версия возвращает 409. После конфликта нужно обновить список и заново открыть форму. Изменение статуса задачи не меняет статус связанного заказа.

Поиск и фильтры задач выполняются сервером. Страница по умолчанию 20, максимум 100. Count и список читаются в RepeatableRead; порядок createdAt DESC, id DESC. Между запросами страниц возможен сдвиг при добавлении записей.

## Хранение и история
Модули team и tasks находятся отдельно от crm. Составные внешние ключи запрещают связывать задачу с исполнителем или заказом другой компании. Миграция 202610080001_team_tasks сохраняет существующим пользователям OWNER, а для новых задаёт безопасный default EMPLOYEE. Demo seed явно создаёт владельца.

В истории фиксируются приглашение, отзыв, присоединение, отключение/включение сотрудника, создание/правка/статус задачи. Бизнес-изменение и событие записываются атомарно; названия задач и имена допускаются как метаданные, описания и секреты не копируются.

## Ограничения и проверки
Это первая модель команды: нет произвольных ролей, доступа менеджера к отдельным клиентам, нескольких компаний у одного аккаунта, восстановления пароля, email-доставки, уведомлений и фонового планировщика. Списки сотрудников/активных приглашений пока без пагинации; перед большим пилотом нужны квоты и пагинация. Комментарии к задачам и вложения не добавлены.

tests/team.integration.mjs проверяет прямые запреты чтения/записи закрытых разделов, изоляцию компаний, скрытые поля, повторное конкурентное принятие, истечение/отзыв, версии задач, переназначение, журнал, отключение/повторный вход и защиту владельца. Playwright проходит создание приглашения, принятие в отдельном браузерном контексте, задачу, выполнение, RU/KK/EN и отключение на мобильной ширине.
