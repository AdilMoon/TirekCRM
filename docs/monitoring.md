# Мониторинг TirekCRM

Локальный Docker-профиль объединяет Prometheus, Grafana и Blackbox Exporter. Grafana показывает API, PostgreSQL, сайт, HTTPS, частоту ошибок, задержки, ресурсы Node.js и очереди доставки. Prometheus хранит показатели до 7 дней в пределах 512 МБ. Панели и история сохраняются в Docker-томах.

## Открыть панели

- Grafana — http://localhost:3100/d/tirek-operations.
- Prometheus — http://localhost:9090. Раздел Alerts показывает состояния правил.
- Логин Grafana — admin. Первоначальный случайный пароль находится в .local/monitoring/grafana-password. Файлы ключей следует хранить вместе с настройками окружения.

Запуск из корня репозитория:

```powershell
npm.cmd run monitoring:up
```

Команда создаёт отсутствующие ключи, сохраняет существующие и запускает профиль monitoring. Обычный docker:up запускает приложение. Уже работающие контейнеры мониторинга имеют политику перезапуска unless-stopped. При изменении Caddyfile работающий HTTPS-прокси обновляют командой:

```powershell
docker compose --env-file .local/docker.env restart caddy
```

## Что проверяется

Сбор показателей и проверки страниц выполняются каждые 15 секунд. Проверка сайта обращается к веб-приложению. Проверка HTTPS проходит через Caddy и запрашивает readiness API с запросом к базе. Проверяется сертификат для localhost по публичному сертификату локального центра. Изолированный контейнер ca-export копирует только публичный сертификат в отдельный том экспортера.

Метрики HTTP содержат метод, шаблон маршрута и статус ответа. Неизвестные пути объединяются в unmatched. Счётчики очередей агрегированы для текущего канала доставки и текущего бота. Для PostgreSQL фиксируются результат и время последнего успешного сбора. При ошибке предыдущие значения очередей сбрасываются и показывается ошибка сбора.

Отдельный ключ /run/secrets/metrics_token защищает /api/ops/metrics. Prometheus использует Authorization: Bearer через secret-файл. Caddy закрывает /api/ops/* с публичного адреса CRM. Доступ к Grafana и Prometheus опубликован только на 127.0.0.1. Сеанс владельца CRM относится к своей организации; отдельный вход Grafana предназначен для администратора платформы и показывает общие показатели.

## Правила тревог

| Сигнал | Условие |
| --- | --- |
| API | Сбор метрик недоступен в течение минуты |
| PostgreSQL | Сбор данных из базы завершается ошибкой в течение минуты |
| Снимок данных | Последний успешный сбор старше минуты, условие сохраняется ещё минуту |
| Сайт или HTTPS | Проверка страницы неуспешна в течение минуты |
| Ошибки сервера | Более 5% ответов 5xx за 5 минут при минимум 20 запросах, условие сохраняется 2 минуты |
| Очередь | Ожидающее сообщение старше 5 минут во включённом канале, условие сохраняется 2 минуты |
| Telegram polling | Последний завершённый poll старше 90 секунд, условие сохраняется 2 минуты |
| Окончательная ошибка доставки | Во включённом канале есть FAILED-сообщения, условие сохраняется минуту |

Сейчас тревоги отображаются в панелях. Отправка тревог конкретному администратору требует выбора получателя и настройки канала. Очередь показывает техническую доставку провайдеру. Прочтение письма или сообщения определяется самим провайдером.

При тревоге сначала проверьте состояние контейнеров и последние сообщения сервиса:

```powershell
docker compose --env-file .local/docker.env --profile monitoring ps
docker compose --env-file .local/docker.env logs --tail 100 api
```

После исправления причины проверьте probe_success, свежесть снимка базы и уменьшение очереди. Состояние FAILED означает исчерпание попыток доставки и требует разбора сообщения. Ключи мониторинга и пользовательские токены хранятся в локальных secret-файлах.

Мониторинг работает на том же компьютере, что и CRM. Наблюдение за выключенным компьютером и круглосуточная эксплуатация потребуют отдельного работающего узла проверки.

## Проверки

Тест сборщика воспроизводит ошибку базы и восстановление. HTTP-тест проверяет отдельную авторизацию, отключённый режим и отсутствие значений URL в метках. Promtool проверяет конфигурацию и воспроизводит срабатывание и восстановление тревог на искусственных рядах. Рабочие сервисы при этих испытаниях продолжают работу.

Проверка панелей в Microsoft Edge:

```powershell
$env:TEST_MONITORING='true'
$env:PLAYWRIGHT_CHANNEL='msedge'
npx.cmd --no-install playwright test tests/browser/monitoring.spec.ts
```

В основу конфигурации положены рекомендации по ограничению меток, официальный клиент Node.js и документация Grafana по secrets и provisioning. [Метки Prometheus](https://prometheus.io/docs/practices/naming/), [клиент Node.js](https://github.com/prometheus/client_js), [Grafana в Docker](https://grafana.com/docs/grafana/latest/setup-grafana/configure-docker/).
