# Почта аккаунта и восстановление доступа

В TirekCRM подключены Gmail SMTP, транзакционная очередь уведомлений и API
восстановления пароля. Отдельная форма регистрации уже существует:
**https://localhost:8443/register**, ссылка на неё — «Создать пространство компании»
на экране входа. У вошедшего пользователя вместо формы показывается переход
в существующее пространство; для новой компании сначала нужно выйти.

## Какие письма отправляются

| Событие | Письмо |
| --- | --- |
| Успешная регистрация компании | Приветствие на email нового владельца |
| Обычная смена пароля | Уведомление на email этого аккаунта, время события и рекомендация проверить доступ |
| Сброс пароля по токену | Уведомление об изменении пароля, без самого пароля или токена |
| Запрос восстановления | Одноразовый токен целевому активному аккаунту; HTTP-ответ его не содержит |

На экране входа доступна ссылка «Забыли пароль?». Форма /reset-password принимает
email и показывает одинаковое сообщение для существующего и неизвестного адреса.
Письмо содержит одноразовую ссылку на ввод нового пароля. Токен передаётся во
фрагменте URL и удаляется из адресной строки при открытии страницы. Успешный
сброс завершает предыдущие сеансы этого аккаунта. После сброса пользователь
входит самостоятельно. При отключённой доставке форма показывает её статус.
Демонстрационный `owner@tirek.local` не является реальным почтовым ящиком.
Для получения писем зарегистрируйте аккаунт с настоящим адресом.

## Настройка Gmail

В локальном `.env` (не в Git):

```dotenv
MAIL_DELIVERY=gmail
GMAIL_USER=your.name@gmail.com
GMAIL_APP_PASSWORD=
MAIL_ENCRYPTION_KEY=
```

GMAIL_APP_PASSWORD — отдельный 16-символьный пароль приложения Google, не обычный
пароль аккаунта. Требуется включённая двухэтапная аутентификация; доступность
паролей приложений зависит от политики Google/Workspace. Создайте пароль
самостоятельно в [Google Account](https://myaccount.google.com/apppasswords), сохраните
в `.env`, не отправляйте его в чат и не коммитьте. [Справка Google](https://support.google.com/accounts/answer/185833).

`npm run setup` создаёт MAIL_ENCRYPTION_KEY, если ключ отсутствует: 32 случайных
байта в hex. Сохраняйте его, пока в очереди есть зашифрованные письма восстановления;
замена ключа делает такие пакеты нечитаемыми. Gmail подключается к smtp.gmail.com:465
с TLS 1.2+, проверкой сертификата и без SMTP debug/logging. OAuth ещё не реализован.
Неверная/неполная конфигурация Gmail останавливает запуск, а не переключает
на незаметную небезопасную доставку. [Настройки Nodemailer](https://nodemailer.com/guides/using-gmail).
В production Gmail требует явно заданный HTTPS WEB_ORIGIN без пути/завершающего слеша.

После изменения `.env` **перезапустите** `npm run dev:https`: существующие процессы
используют загруженные переменные окружения. Проверочная команда:

```sh
npm run mail:test
```

Она отправляет одно тестовое письмо на сам GMAIL_USER. Требуется собранный backend
(`npm run setup` или `npm run build -w @tirek/api`). Пароли и ошибки провайдера
в консоль не печатаются. SMTP acceptance не является общей гарантией доставки
во входящие; у Gmail есть собственные ограничения/антиспам. Подключение этой
локальной копии проверено: тестовое письмо найдено во «Входящих» отправителя.

Ссылки в письмах строятся только из WEB_ORIGIN, не из клиентского Host. Для локального
проекта localhost доступен на этом компьютере; внешним пользователям нужен домен
и отдельное размещение приложения.

## Режимы и очередь

- `MAIL_DELIVERY=local`: уведомления записываются в `.local/mail/notifications`,
  локальные токены — в `.local/mail/password-reset`. Реальных отправок нет.
- `MAIL_DELIVERY=gmail`: сообщения доставляются через настроенный Gmail.
- `MAIL_DELIVERY=disabled`: новые уведомления не ставятся в очередь, восстановление
  по умолчанию выключено. Без переменной это режим production; в разработке — local.
- Локальная доставка в production запрещена, даже при явном выборе.
- Необязательный `PASSWORD_RESET_DELIVERY=disabled` выключает только восстановление.
  Для Gmail-восстановления должен быть настроен общий Gmail-режим.

Регистрация/смена пароля и строка MailMessage фиксируются в одной транзакции.
SMTP не вызывается внутри бизнес-транзакции. Недоступность Gmail не откатывает
созданный аккаунт: письмо остаётся в очереди. Если не удаётся записать саму очередь
в БД, транзакция не подтверждается. Обработчик запускается вместе с API, проверяет
очередь каждые 5 секунд, берёт до 10 писем за проход по одному с арендой на 60 секунд.

Неуспешная доставка повторяется с паузами 1/2/4/8/16 минут; после шестой неудачи
письмо получает FAILED. Автоматического бесконечного повтора и публичного API
рассылки произвольных писем нет. Lease-token защищает подтверждение чужой попытки.
При сбое процесса после SMTP acceptance, но до записи SENT, возможен повтор:
доставка имеет семантику «как минимум один раз», не гарантирует exactly-once.
Message-ID стабилен для повторов одного письма, но дедупликация провайдером не гарантирована.

Режим сохраняется в каждой записи: локальные тестовые письма после включения Gmail
не отправляются в настоящую почту. Поля recipient/userId/organizationId связаны
с пользователем составным FK. Публичного чтения очереди нет. В ошибках хранятся
только безопасные коды, без SMTP-ответа, адресов, паролей или токенов.

## API восстановления

Все ответы запрещают кэширование. POST требуют тот же допустимый Origin, что остальные
мутации. Автоматического входа и выдачи новой cookie после сброса нет.

| Метод | Маршрут | Тело / результат |
| --- | --- | --- |
| GET | /api/auth/password-reset/status | `{enabled:boolean}` |
| POST | /api/auth/password-reset/request | `{email}` → 202 `{ok:true}` |
| POST | /api/auth/password-reset/confirm | `{token,newPassword}` → 200 `{ok:true}` |

Email приводится к нижнему регистру и trim. Существующий, неизвестный,
неактивный аккаунт и запрос во время cooldown получают одинаковый публичный ответ.
Ограничение request — 5 запросов/минуту с IP, confirm — 10/минуту. Повторная выдача
для аккаунта — не чаще раза в минуту. Запрос выдерживает минимальную задержку
250–275 мс; это не доказательство абсолютной временной неразличимости под нагрузкой.
Gmail работает в фоне: время SMTP не отражается в ответе request.

Токен — 32 случайных байта, представленных 64 hex-символами; действует 15 минут,
один раз и только для связанного пользователя. В PasswordReset хранится SHA-256
и отпечаток текущего хеша пароля. В SMTP-очереди токен дополнительно находится в
AES-256-GCM-пакете с отдельным ключом из `.env`, привязанном к id письма и пользователя;
открытого токена в БД нет. Перед отправкой проверяются срок, активность аккаунта и
текущий токен. После доставки/пропуска/финального отказа зашифрованный пакет удаляется.

Новый пароль — 12–128 символов. Пользователя, роль и организацию нельзя передать
в теле confirm. Смена хеша, удаление всех сеансов, потребление токена, аудит и
уведомление выполняются атомарно. Обычная смена пароля тоже удаляет ожидающий токен.
Неизвестный, использованный, истёкший токен, блокировка аккаунта и изменение прежних
учётных данных дают одну ошибку 400. Выключенная доставка даёт 503, лимит — 429
с Retry-After. После успешного сброса пользователь входит обычным способом.

В локальном режиме JSON-файл содержит token для ручной проверки API. Он не является
публичным файлом приложения. Запрашиваются POSIX-права 0700/0600; на Windows действуют
ACL каталога пользователя, а не гарантия POSIX mode. `.local` и `.env` исключены из Git;
не раздавайте доступ к ним и очищайте отработанные локальные письма по своей политике.

## Границы итерации

Не добавлены подтверждение email, доставка приглашений, MFA, уведомления о каждом
входе, управление очередью в UI и пользовательская форма сброса. Приветствие не
подтверждает адрес, а почтовая доставка не заменяет права доступа. Размещение/лимиты
и обработку персональных данных внешним провайдером нужно оценить для production.
Закрытые ключи и пароли приложения остаются только в локальном окружении.

Проверки и ограничения — в [адверсариальном ревью](reviews/2026-11-02-account-mail-recovery.md).
Основа сценария: [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
