# Адверсариальное ревью: локальный HTTPS — 2026-11-02

## Область и результат

По запросу пользователя настроен HTTPS на текущем компьютере. Изменения отдельно
перечитаны с проверкой недоверенных заголовков, Origin, cookie, закрытых ключей,
слушателей, редиректов и запуска процессов. Caddy 2.11.7 завершает TLS на localhost,
внутренние Next/Nest работают по loopback. Публичного размещения нет.

## Проверенные предположения и исправления

- Прежний `Secure` зависел только от production, поэтому локальный TLS сам по себе
  не обеспечивал этот флаг. Теперь cookie и CSRF используют один валидируемый
  WEB_ORIGIN. Проверена настоящая Set-Cookie и cookie браузера.
- Прежний HTTP-alias `127.0.0.1:3000` разрешался и при HTTPS-конфигурации. Теперь он
  разрешён только в исходном HTTP-профиле. Отсутствующий/чужой/HTTP Origin и Origin
  с другим портом или путём отвергаются. `X-Forwarded-Proto` не влияет на решение;
  глобальное доверие прокси не включалось.
- При занятом порте Next.js мог перейти на другой порт, оставив TLS-прокси перед
  посторонним приложением на 3000. Добавлены явный порт Next.js и предварительная
  проверка портов. Повторный запуск при работающем профиле воспроизведён: отказ
  `Port 3000 is busy`, действующий сервер продолжил отвечать.
- Редирект задаёт постоянный hostname, а не отражает Host. Проверены сохранение
  пути/query и запрос с чужим Host. Caddy/admin выключен, все слушатели проверены:
  8080/8443 — только 127.0.0.1 и ::1; 3000/4000 — только 127.0.0.1.
- Локальный HSTS удаляется и с ответов API: политика для hostname распространилась
  бы на HTTP-порт разработки. Наличие no-store на API сохранено.
- Windows запрещает выполнение .ps1 по умолчанию. Первоначальный вариант установщика
  заменён Node.js-скриптом; системная политика не менялась. Архив официального Caddy
  проверяется закреплённым SHA-512 до извлечения и выполнения. Ключи создаёт сам Caddy
  в игнорируемом `.local/caddy`. Доверие установлено только текущему пользователю
  Windows, системное хранилище компьютера не изменялось.
- Браузерный тест потерянного ответа содержал HTTP-Origin и прямой HTTP API.
  После перехода теста на HTTPS получен 403; исправлен тестовый запрос, чтобы он
  использовал реальный URL перехваченного запроса и Origin выбранного baseURL.
  Защита приложения не ослаблялась; повторный прогон всех трёх сценариев успешен.

## Выполненные проверки

- `npm ci`, `npm run setup`, `npm run https:setup`: успешны после настройки PATH
  только для процесса проверки. Валидатор Caddy принял конфигурацию.
- `npm run check:structure`: зависимости между слоями и 610 переводов проверены.
- `npm run typecheck`, `npm test` (10 тестов), `npm run build`: успешны.
- `npm run test:https`: TLS 1.2/1.3, отказ TLS 1.1, отказ недоверенного CA,
  проверка сертификата с явным CA, HTML/API, редирект, Host, Origin и no-store.
- `security.integration.mjs`, `cache-policy.integration.mjs`, `team.integration.mjs`
  через `https://localhost:8443/api`: 21 тест, все успешны. Проверены границы
  организаций/ролей, отзыв сессий, смена пароля, конкурирующие входы и повторы.
- `onboarding.spec.ts` в установленном Microsoft Edge через HTTPS: 3/3, включая
  регистрацию RU/KK/EN, мобильный/настольный интерфейс, потерянный ответ и повторный
  вход. `ignoreHTTPSErrors` не включался; проверены HttpOnly, Secure и isSecureContext.
- Windows `Invoke-WebRequest https://localhost:8443/api/health`: 200 без отключения
  проверки сертификатов. Подтверждено доверие ОС, а не только тестового Node.js CA.
- `node --check` для новых .mjs и `git diff --check`: успешны.

## Данные, секреты и ограничения

Создана отдельная локальная БД в новой копии репозитория; применены существующие
миграции. Seed не запускался. Интеграционные и браузерные тесты изменяли и удаляли
только созданные ими организации. Организации, деньги, даты и бизнес-операции в коде
не менялись; полный повтор всех финансовых сценариев не проводился.

Перед коммитом проверяется явный список исходников/документации. `.env`, CA/ключи,
бинарный Caddy, БД, зависимости, кэши, сборки и test-results остаются вне индекса;
проверяется отсутствие приватных ключей и токенов в добавленных строках. SHA-512
официальных архивов являются публичными контрольными суммами, а не секретами.
Сгенерированные Next.js файлы инструкций и dev-пути next-env не входят в изменение.

Сертификат предназначен для localhost этой копии проекта. Для другого пользователя,
браузера с собственным trust store или другой копии нужно отдельное доверие.
Установщик выполнен на Windows x64; ARM64 и Linux/macOS здесь не проверялись.
Автопродление обеспечивается штатным Caddy; ожидание полного срока сертификата
не проводилось. HTTP между локальными процессами остаётся; профиль не защищает
от программ с доступом к аккаунту ОС и закрытому ключу CA. Распределённые лимиты,
публичный домен, production HSTS, деплой и внешний пентест не входят в эту задачу.
Успешные проверки не гарантируют безопасность всего приложения или готовность к
коммерческому запуску.
