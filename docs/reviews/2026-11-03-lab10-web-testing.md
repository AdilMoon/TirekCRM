# Лабораторная работа 10 и проверки Microsoft Edge

## Область

Отдельный набор UI-тестов, ограничение длины общего поиска и чтение финансового отчёта одним SQL-запросом. По уточнению пользователя итоговая конфигурация использует только Microsoft Edge. Содержание задания сверено со страницами 23–25 предоставленного PDF; Word-отчёт готовится на казахском и хранится отдельно от исходного кода.

## Воспроизведённые проблемы

- DEF-UI-01: TC11 до исправления сохранил 201 символ в поле поиска, HTTP 400 и assertion `expected length 200, received 201`. Добавлен `maxLength={200}`. Прямая отправка 201 символа в API по-прежнему даёт 400, допустимый поиск возвращает 200, очистка и следующий поиск восстанавливают список.
- DEF-API-02: полный regression оставлял финансовую таблицу в состоянии загрузки. Ожидание точного ответа на запрос показало HTTP 500; безопасный серверный журнал зафиксировал `DATABASE_ERROR/P2028`. Два чтения в транзакции заменены одним statement с общим `filtered` CTE, итогами и LEFT JOIN страницы. После изменения полный regression и интеграционные сценарии отчётов прошли.
- При наладке тестов параллельные запуски очищали общую папку артефактов. Лабораторные артефакты перенесены в `.local/lab10/run`, отдельные наборы запускаются последовательно. Защитные лимиты не отключались; перед набором ожидается реальное окно входа.

## Адверсариальное перечитывание

- Организация берётся из прежнего контекста OWNER; все четыре источника движений сохраняют параметризованные фильтры организации. Проверены чужая организация, EMPLOYEE, подмена tenant/query и снимки документов после изменения клиента.
- LIMIT/OFFSET, поиск, категория, вид операции, даты и orderId остаются параметрами SQL. Проверены пустая выборка и страница за пределами списка; LEFT JOIN возвращает итоги даже при отсутствии строк страницы.
- Итоги рассчитываются в SQL NUMERIC, строки форматируются Decimal.toFixed(2). В JSON строки не попадают повторяющиеся поля итогов: интеграционный тест проверяет точный набор полей. Суммы, дробные тиыны, исторические границы Алматы и повторяющиеся UUID разных источников проверены существующим API-набором.
- Один statement читает один MVCC snapshot. Исходные платежи, расходы, возвраты и сторно не изменяются. Повторный GET не создаёт финансовых записей; механизмы идемпотентности записей не затронуты.
- UI ограничивает ввод, но серверная валидация сохраняется. Проверены пустые поля, email, несовпадающие пароли, пробельное имя, 200/201 символ, выход и последующий API 401, отсутствие чужих клиентов, восстановление после управляемого 503.
- Тесты создают собственные UUID и одноразовые адреса `.invalid`. Cleanup использует только эти UUID и точные email, в том числе при потере наблюдаемого ответа регистрации. Сервер запущен с local-почтой, текущий `.env` с Gmail не изменялся.
- Сертификаты проверяются, `ignoreHTTPSErrors` не включён; cookie проверены как Secure/HttpOnly. HTML, JSON, PNG и trace остаются в игнорируемых каталогах.

## Проверки и ограничения

Итоговый набор: 12 UI-сценариев Edge; 9 regression-сценариев workspace/onboarding; 6 интеграционных сценариев отчётов (Node runner также считает родительский suite); 15 backend unit и 3 localization. Обязательные check:structure, typecheck, npm test и build выполнены перед коммитом. Секреты и состав индекса проверены перед отправкой.

Результат относится к локальному окружению, выбранным сценариям и Microsoft Edge. Полный cross-browser, физические мобильные устройства, нагрузочное тестирование, полный аудит безопасности и покрытие всего кода не заявляются. Успешные тесты не являются гарантией безопасности или готовности к коммерческому запуску.
