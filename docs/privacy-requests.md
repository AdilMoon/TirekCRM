# Реестр обращений по персональным данным

Реализовано 25.10.2026. Раздел «Настройки → Обращения по персональным данным» доступен владельцу компании. Это внутренний журнал обработки, а не публичная форма и не автоматическое исполнение правовых запросов.

## Пользовательский сценарий

1. Владелец проверяет личность, полномочия и основание запроса вне системы и регистрирует обращение: имя, необязательный контакт, вид, содержание, дата получения и необязательный срок ответа.
2. Виды: доступ, исправление, удаление, отзыв согласия, другое. Начальный статус — «Получено». Можно перевести в обработку либо сразу закрыть как исполненное / отказ с обоснованием.
3. Для закрытия обязателен результат или основание отказа. Статус фиксируется после фактической обработки и ответа. Реестр сам не отправляет сообщения, не выдаёт выгрузки и не изменяет клиентов, счета или платежи.
4. Поиск по имени, статус, фильтр просроченных, страницы по 5 записей. Сначала ближайшие сроки, записи без срока — в конце. Просрочено только незакрытое обращение со сроком раньше текущей календарной даты Алматы; сегодняшний срок ещё не просрочен.
5. Карточка показывает содержание, контакт, результат, автора регистрации и историю переходов. Интерфейс RU/KK/EN адаптирован для телефона.

## API и ограничения данных

Все маршруты требуют действующий сеанс OWNER; организация берётся только из сеанса. Для записи нужен разрешённый Origin. Сотрудник получает 403, чужой идентификатор — 404.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | /api/privacy-requests | page, pageSize, q, status, overdue=true/false; минимальные карточки без контакта, содержания и результата |
| GET | /api/privacy-requests/:id | Подробная карточка своей организации |
| POST | /api/privacy-requests | kind, subjectName, contact?, description, receivedOn, dueOn?, idempotencyKey |
| PATCH | /api/privacy-requests/:id | version, status, resolution?, idempotencyKey |

Имя — 1–160, контакт — до 200, содержание — 3–1000, результат — 3–1000 символов при закрытии. Краевые пробелы удаляются; управляющие символы, кроме переноса строки/табуляции, и непарные UTF-16 суррогаты запрещены. Неизвестные поля отклоняются. Даты ISO YYYY-MM-DD не раньше 1900-01-01; получение не в будущем, срок не раньше получения. Срок выбирает владелец с учётом конкретного запроса: юридический календарь система не рассчитывает.

## Согласованность и доступ

- Создание, изменение и аудит атомарны в Serializable-транзакции с ограниченными повторами. Активная роль владельца повторно проверяется внутри записи.
- UUID-ключ создания уникален в организации. Тот же ключ и те же нормализованные поля возвращают существующее обращение; другой запрос с этим ключом — 409.
- Изменения защищены версией. Два разных конкурентных перехода одной версии дают один успех и один конфликт. Закрытое обращение нельзя открыть заново.
- Отдельные подтверждения изменений хранят ключ, автора, идентификатор обращения и хеш нормализованного ввода. Повтор уже выполненного перехода возвращает текущее состояние, даже если после него были другие переходы. Устаревший повтор не откатывает статус. Хеш не означает анонимизацию данных.
- После первой отправки форма удерживает тот же ключ и тело запроса. При неопределённом исходе поля блокируются, доступен повтор. Ключ живёт только в открытой форме: после закрытия окна/перезагрузки нужно проверить реестр перед новой регистрацией; это объясняется в интерфейсе.
- Контакт, содержание и результат не дублируются в метаданных аудита. Аудит содержит вид/статус либо переход, автора и время. При отказе доступа к карточке она не отображает ранее загруженные подробности после ответа 401/403/404 на изменение.
- Связь подтверждения с обращением включает organizationId. Нельзя связать подтверждение одной организации с обращением другой даже прямой записью в БД.

## Границы этой итерации

Нет редактирования исходных реквизитов обращения, переноса срока, повторного открытия, вложений и автоматической отправки ответа. Просрочка пересчитывается при запросе/обновлении списка, без фонового уведомления и автоматического обновления в полночь. Поиск использует contains/ILIKE как существующие реестры; нагрузочный профиль ещё не измерялся. Пагинация offset не фиксирует снимок между отдельными запросами страниц.

Это не реестр согласий/оснований обработки и не подтверждение выполнения запроса. Сроки хранения самого реестра, подтверждений и резервных копий должны быть определены до внешнего пилота. Реестр добавляет персональные данные заявителя; не следует загружать удостоверения, пароли и избыточные сведения. Оператор, размещение в РК, пользовательская политика, проверка восстановления и остальные условия из [матрицы пилота](pilot-readiness-kz.md) остаются открытыми.

Проверки и ограничения: [адверсариальное ревью](reviews/2026-10-25-privacy-requests.md).
