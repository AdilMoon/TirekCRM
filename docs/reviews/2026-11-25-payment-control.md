# Адверсариальное ревью: контроль оплат

Дата: 25 ноября 2026. Изменения перечитаны после реализации: SQL отчёта, контракт и guard, подключение финансового экрана, переводы и сценарии Edge.

## Опровергнутые предположения и исправления

1. **Сумма счетов равна долгу заказа.** Это неверно: повторный счёт содержит снимок того же заказа. Реализация вообще не суммирует счета; считает текущую стоимость за вычетом платежей с возвратами. На одном заказе несколько счетов, платежей и возвратов не умножают остаток.
2. **Можно взять последний неаннулированный счёт.** Тогда аннулирование нового счёта неожиданно восстановит срок старого. Выбор сначала находит последний счёт независимо от статуса; аннулирование убирает срок, старый не используется. Отдельно проверены отсутствие даты, акт после счёта и одинаковые timestamps (порядок по номеру).
3. **Срок сегодня можно назвать «не наступил».** При повторном чтении обнаружена неточная подпись; заменена на «Срок не прошёл». Сравнение строго `<`, сегодня не просрочено. Время PostgreSQL явно переводится в Алматы.
4. **Обёртка label гарантирует точное доступное имя select.** Первый реальный прогон Edge воспроизвёл ошибку: имя включало текст вариантов. Добавлен явный `aria-label`, повторный сценарий выбирает срок по точному имени.
5. **Скриншот сразу после смены языка показывает готовые данные.** При визуальном просмотре обнаружен снимок загрузки. Проверка исправлена: ждёт реальную строку с длинным текстом на каждом языке, затем проверяет ширину и сохраняет мобильный снимок. Также исправлено имя региона в тесте, которое само меняется с языком.

## Границы и данные

- Реальный HTTP: без сессии 401, сотрудник 403, другой владелец видит пустую свою организацию. Поле `organizationId` и неизвестный статус отвергаются схемой (400). Сессию и активность пользователя проверяет общий SessionGuard. Финансовые данные не кэшируются (`no-store`).
- SQL-параметры используются для всех пользовательских значений. Поиск `x' OR 1=1 --` и `%` не расширяет область выборки. Длинный заголовок с HTML остаётся текстом React; в строках нет добавленных script/img.
- Один запрос читает единый MVCC-снимок: конкурентная запись не может попасть только в итоги или только в строки одного ответа. Чтение не создаёт денег, документов или уведомлений, поэтому повтор GET не имеет побочных эффектов. Существующая запись оплаты с идемпотентностью используется без изменений.
- Проверены 110 заказов, положительные/нулевые остатки, отмена, бесплатный повторный выезд, полная оплата, несколько возвратов и повторная оплата. Сумма `1060000000000000008.96` возвращается точно, без JS Number. Итоги сохраняются даже для пустой страницы за концом выборки.
- Чистка ограничена созданными тестами организациями. Контрольные хеши рабочих заказов, клиентов, организаций и задач плюс количества/суммы пользователей, оплат, расходов и фото сравниваются до и после Docker-обновления; содержимое рабочих записей не выводится.

## Оставшиеся ограничения

Срок черновика — средство внутреннего контроля, не доказательство юридического долга. Нет банковской сверки, автоматических писем, привязки платежей к отдельным счетам и автоматического обновления в полночь: доступна кнопка обновления. Историческая или текущая переплата не показывается как задолженность. Лимит маршрута общий для IP; распределённое ограничение нагрузки не добавлялось. Функциональный объём 110 заказов не заменяет нагрузочное испытание большого рынка. Успешные проверки не являются гарантией безопасности или коммерческой готовности.
